# 科学计算任务运营服务

这是一个面向科研平台、实验室和计算中心的 Python 后端，使用 FastAPI 与 SQLite 管理参数模板、计算任务提交、优先级排队、工作者领取、取消、失败重试、租约恢复、用户配额、结果版本和管理员人工干预记录。服务同时提供**卫星功率预算管理**：登记载荷与日照段、接受带功耗曲线的推理作业、在 1 千瓦功率预算下计算峰值与累计能耗、解释拒绝原因，并在预算调整后重新评估且不篡改原始申请。服务同时保留用户、角色、会话和审计等基础能力，所有运行数据都在单个本地数据库文件中，不需要另行部署数据库、缓存、消息队列或浏览器界面。

## 卫星功率预算能力

- 基础登记：维护活动载荷（恒定基线功耗）、日照段（不允许时间重叠）和临时降额窗口；初始预算为日照/地影各 1000W，可通过预算修订调整。
- 作业申请：作业由顺序连接的恒定功耗阶段（功耗曲线）组成，支持跨多个日照段；每次修订只追加新版本，原始申请与历次修订均保留。
- 预算计算（公式版本 `satellite-power-budget/v1.0.0`）：
  - 时间轴按日照/地影/降额边界和作业阶段边界切片，逐片叠加活动作业功耗与载荷基线；
  - 输出全局峰值、峰值时刻、总能耗、日照/地影分摊能耗与每作业峰值/能耗；
  - 判定三类违规：瞬时功率超限（日照、地影、叠加降额取更严上限）、载荷基线自身超限、连续地影放电超过电池可用容量（容量 × 最大放电深度）；
  - 每条违规给出人类可读的拒绝原因、时间区间、超出量和主要责任作业，仅被判定为责任方的作业标记为不可执行，并给出可执行顺序。
- 重新评估：预算调整生成新的预算修订号；可用当前或历史预算版本重评，评估结果只追加记录，绝不回改作业申请。
- 计划草案与发布：计划内容（作业清单）每次修改生成新版本，支持版本比较（新增/移除/顺序变化）；只有评估可行的草案可以审批发布，发布前可撤回；重复发布、撤回后发布、过期版本提交均明确返回 `409 conflict`。
- 计算可追溯：每次评估保存完整输入快照（预算修订、载荷、日照段、降额、作业及作业修订号）、快照摘要（SHA-256）、公式版本和结果；管理员可按编号或主题查询。

## 已有能力

- 参数模板：保存参数类型、必填项、数值范围、默认值、最大运行时间和最大尝试次数。
- 任务提交：根据模板校验参数，使用用户与幂等键避免重复创建，并保存项目、提交人和输入摘要。
- 排队领取：按优先级和进入队列的顺序分配任务，工作者可声明算法能力并获得有期限的租约。
- 执行回执：工作者可以续租、提交结果或报告失败；可重试错误使用确定的退避时间重新排队。
- 失败恢复：租约过期后可由恢复入口将任务重新排队，达到最大尝试次数的任务转为失败。
- 配额控制：可保存用户、角色或项目的排队数、运行数和每日提交上限；当前提交路径执行用户配额。
- 结果版本：每次成功回执保存不可变结果、指标摘要和内容摘要，任务指向当前结果版本。
- 人工干预：取消、人工重试、优先级调整和批量操作均保留操作者、原因、前后状态和批次标识。
- 登录与角色：基础管理模块提供管理员初始化、用户、角色、会话和细粒度权限。

## 运行环境

- Python 3.11
- SQLite 3，由 Python 标准库提供
- Linux、macOS 或 Windows

## 安装

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
```

默认数据库位于 `./data/compute-operations.db`。可以复制 `.env.example` 并通过 `TOWNSHIP_DATABASE_PATH` 指定其他本地路径。

## 数据库初始化与检查

```bash
python -m app.cli init-db
python -m app.cli check-db
```

## 启动 API

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8432
```

健康检查：

```bash
curl -sS http://127.0.0.1:8432/api/system/health
```

计算任务摘要位于 `/api/compute/summary`，模板、配额、提交、领取、回执和人工操作接口统一使用 `/api/compute` 前缀。

卫星功率预算接口统一使用 `/api/power` 前缀，主要入口：

| 能力 | 接口 |
| --- | --- |
| 载荷登记/查询/修订（乐观版本） | `POST/GET /api/power/payloads`、`PUT /api/power/payloads/{code}` |
| 日照段、临时降额 | `POST/GET /api/power/sun-windows`、`POST/GET /api/power/deratings` |
| 预算当前版本/历史/调整 | `GET /api/power/budget`、`GET/POST /api/power/budget/revisions` |
| 作业申请、修订、版本比较 | `POST/GET /api/power/jobs`、`POST /api/power/jobs/{code}/amendments`、`GET /api/power/jobs/{code}/revisions/compare` |
| 作业评估与重评 | `POST /api/power/jobs/{code}/evaluations`、`POST /api/power/recheck/job/{code}` |
| 计划草案/发布/撤回 | `POST/GET /api/power/plans`、`PUT /api/power/plans/{id}`、`POST /api/power/plans/{id}/publish|withdraw` |
| 计划版本比较 | `GET /api/power/plans/{id}/versions/compare` |
| 评估快照与公式版本追溯 | `GET /api/power/evaluations`、`GET /api/power/evaluations/{id}` |

冲突提交（过期版本号、重复发布、撤回后发布、日照段重叠等）统一返回 `409` 并在 `error.context` 中给出当前版本或冲突对象，不会静默覆盖。

## API 冒烟

```bash
python -m app.cli smoke
python -m app.cli compute-demo
python -m app.cli power-demo
```

`smoke` 在进程内检查根路径和健康接口，`compute-demo` 会创建示例参数模板、提交一个计算任务并让匹配能力的工作者领取，用于快速确认核心运营链路；`power-demo` 会登记载荷与日照段、提交一条带两阶段功耗曲线的推理作业并返回峰值、累计能耗、可执行顺序、公式版本和评估记录编号。

## 数据一致性

SQLite 连接启用外键、WAL、busy timeout 和同步写入策略。提交、领取、回执和人工干预使用即时事务；任务领取通过条件更新避免同一条排队记录被重复领取。服务保存 UTC 时间字符串，测试可以注入固定时钟验证退避、租约到期和跨日配额。会话令牌只保存摘要，审计与人工干预记录不会写入明文密码或令牌。

功率预算模块同样使用即时事务：作业申请与计划内容只追加不可变修订/版本，预算调整只追加预算修订号；载荷、作业、计划和预算的并发提交都要求携带期望版本号，过期提交返回 `409` 而不是后写覆盖先写。每次评估在同一事务内把输入快照、快照 SHA-256 摘要、公式版本和结果写入 `power_evaluations`；计划发布被拒绝时评估记录仍然保留，管理员可凭返回的 `evaluation_id` 复盘当时使用的全部输入。
